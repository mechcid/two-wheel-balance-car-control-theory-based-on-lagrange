# 数值仿真与 LQR：按代码顺序阅读

这份说明对应 `lqr_simulation.py` 的当前实现。重点是解释程序在做什么，不重新推导机器人力学。

建议先读第1、2节和第6节，再看主程序；可控性和 Riccati 方程的细节可以稍后读。

## 1. 这里的“仿真”究竟在做什么？

理论推导给出了一条规则：**如果知道当前状态和输入，就能计算当前状态变化率**。

本程序使用你的局部模型：

$$M_0\delta\ddot z+C_0\delta\dot z+K_0\delta z=B_0u,$$

将其整理成：

$$\dot X=AX+Bu.$$

你提供初始状态，程序求出之后各个时刻的状态。计算结果是一组随时间变化的数值；把这些数值连起来，就是图上的曲线。

这不是机器人三维动画，也没有模拟几何碰撞。现在验证的是“你给定的局部微分方程会怎样随时间演化”。程序不会在每个时刻重新运行 SymPy 推导。

两种实验的区别：

- **开环**：把两轮力矩始终设为零，看受到初始扰动的车是否自行恢复。
- **闭环**：根据当前六个状态不断给出力矩 `u=-K@X`，看能否返回平衡点。

控制器输出是由状态算出来的，没有人为预先画好一条力矩曲线。数学上是理想连续反馈，尚未涉及传感器估计、离散采样或电机饱和。

## 2. 先认清程序中每个数组装什么

状态顺序固定为：

$$X=[x,\psi,\theta,\dot x,\dot\psi,\dot\theta]^T.$$

它们都是相对于静止平衡点的扰动；程序为简洁省略了 delta。当前位置为零表示“回到参考位置”，不是回到某个绝对地图原点。

| Python 下标 | 物理量 | 单位 |
|---|---|---|
| `X[0]` | x 位置扰动 | m |
| `X[1]` | 偏航角扰动 | rad |
| `X[2]` | 俯仰角扰动 | rad |
| `X[3]` | x 方向速度 | m/s |
| `X[4]` | 偏航角速度 | rad/s |
| `X[5]` | 俯仰角速度 | rad/s |

输入 `u=[tau_L,tau_R]`，单位 N·m。

代码的 x 保留原符号模型的**世界 x**定义。默认 `psi0=0`，此时与名义前进方向重合。若改变 `psi0`，不能直接把同一 x 改叫沿车头的里程。矩阵中的 sec(psi0) 因子正是这个约定的结果。

| 名称 | 数组形状 | 用途 |
|---|---|---|
| `M0,C0,K0` | 3×3 | 二阶力学方程的质量、速度项、位置项矩阵 |
| `B0` | 3×2 | 两个电机力矩映射到三个广义方向 |
| `A` | 6×6 | 无输入时，状态如何改变 |
| `B` | 6×2 | 输入如何影响状态变化率 |
| `gain` / `K_LQR` | 2×6 | 六个状态如何组合成两个控制力矩 |
| `Q` | 6×6 | LQR 对状态误差的惩罚 |
| `R` | 2×2 | LQR 对力矩使用的惩罚 |
| `P` | 6×6 | Riccati 方程的解，用来计算反馈增益 |

**别把 `K0` 和 `K_LQR` 混为一谈**：前者是力学模型的位置项矩阵，后者是控制器。`B0` 和 `B` 也不是同一个矩阵。

单个时刻的 X 在数值代码中通常是形状 `(6,)` 的一维数组，数学上按六维列向量理解。整条时序 `X` 是 `(6,1001)`：一行一个状态，一列一个时刻。因此 `X[2,:]` 是俯仰曲线，`X[:,-1]` 是末时刻六状态。

`@` 表示矩阵乘法；`*` 对 NumPy 数组通常是逐元素乘法。`.T` 是转置，`np.diag` 把一组数放到对角线上。

## 4. 从力学矩阵到可积分的程序

### 4.1 `build_M0()`：代入参数，得到质量矩阵

输入参数对象，输出3×3数值矩阵。这里是把推导中的公式翻译为 NumPy 表达式，没有重新做符号推导。

`wheel_mass=(I_Lyy+I_Ryy)/r**2` 的量纲为质量，是轮自转惯量通过滚动关系体现出的等效惯性。

`coupling` 收集左右轮质量与惯量不对称引起的耦合；当前对称示例中它等于零。

函数检查参数是否有限、正值，并排除 cos(psi0) 接近零的坐标奇异情形。正参数不是所有物理一致性条件的完整检查，后面还会检验质量矩阵正定性。

### 4.2 `build_state_space()`：构造 A、B

输入机器人参数，返回 `M0,C0,K0,B0,A,B`。

$$A=\begin{bmatrix}0&I\\-M_0^{-1}K_0&-M_0^{-1}C_0\end{bmatrix},\qquad
B=\begin{bmatrix}0\\M_0^{-1}B_0\end{bmatrix}.$$

上三行是“位置导数等于速度”；下三行是力学方程给出的加速度。

`np.block` 拼出 A 的四个块，`np.vstack` 上下拼出 B。`np.linalg.solve(M0,K0)` 直接求解 `M0@Y=K0`，返回 Y；相当于数学表达式 M0⁻¹K0，但不显式构造逆矩阵。

C0=0 表示**这个局部模型没有速度线性项**，不表示车在闭环下一定无法衰减：控制器可以通过速度反馈产生衰减。

### 4.3 `check_system()`：积分前的检查

它不模拟时间演化，而是检查：

- 维度是否匹配，有无 NaN 或无穷大。
- M0 是否对称、正定。Cholesky 分解成功说明当前数值矩阵正定，从而可逆。
- M0 的行列式、特征值和条件数。
- A 的特征值，是否有正实部模态。
- 可控性矩阵 `[B,AB,...,A^5B]` 的秩是否为6。

当前质量矩阵条件数约29.45。它说明解线性方程时误差放大的敏感程度，数值也会随位置/角度单位和坐标缩放改变，不能单独作为机械设计好坏指标。

当前 A 有正特征值 +6.12016，其对应模态按 exp(6.12016*t) 增长。零特征值不代表所有状态都能自动保持不变：积分链可能产生随时间增长的位移。

可控性秩6表示：对这个理想线性模型，两个输入足以影响全部六个状态方向。它不意味着有力矩上限时任何动作都能实现，也不等于实车验证。

`raise` 或 `assert` 会在检查失败时停止脚本，避免带着错误继续画图。

## 5. 时间响应与控制器分别怎样算出来？

### 5.1 `integrate()`：公共时间积分器

输入常矩阵 F、初值 X0、时长和可选停止事件，求解：

$$\dot X=FX,\qquad X(0)=X_0.$$

开环传 F=A，闭环传 F=A-BK。

`lambda t,X:F@X` 是一个小函数：求解器给它时间和当前状态，它返回当前导数。时间 t 在本模型的右端没有显式出现，但求解器要求这个接口。

`solve_ivp` 会反复估算导数、推进状态，并依据误差估计调整步长。这里的 DOP853 是高阶显式 Runge–Kutta 积分方法。

要分清三个时间概念：

- **内部积分步长**：求解器自己调整，`max_step=0.02` 只规定上限。
- **绘图采样时刻**：`linspace(...,1001)` 取1001个均匀点，从求解器保存的连续插值中读取状态。
- **控制器采样周期**：本程序没有这一项，它模拟的是理想连续反馈。

所以1001个输出点既不是“控制器运行1001次”，也不是“求解器只计算1001步”。

对常矩阵系统有独立计算方式 `expm(F*t)@X0`。程序在五个输出时刻用这个矩阵指数解与 solve_ivp 对比。它核查的是积分实现，不是证明原始机械模型就一定正确。

### 5.2 `simulate_open_loop()`：关闭电机后会怎样

输入 A，使用 u=0；以0.03 rad俯仰扰动开始。

事件函数为 `0.20-abs(theta)`。当其由正变为零，表示角度达到展示阈值；`terminal=True` 要求停止积分。

因此虽然最长时间设置为3秒，当前开环图只画到约0.4223秒。程序没有崩溃，也不是小车停止运动，而是人为停止继续外推这个局部模型。

### 5.3 `design_lqr()`：计算反馈增益

LQR 选择一个常矩阵 K，使理想线性系统下的无限时间代价最小：

$$J=\int_0^\infty(X^TQX+u^TRu)\,dt,\qquad u=-KX.$$

Q 衡量状态偏离的代价；R 衡量使用力矩的代价。权重是设计选择，不是质量、惯量或电机参数。

当前 theta 和 thetadot 权重较高。不同状态单位不同，不能只比较权重数字大小就断言实际贡献大小；实际贡献还取决于状态幅值。

求解器不是用随机力矩训练控制器。它求连续代数 Riccati 方程：

$$A^TP+PA-PBR^{-1}B^TP+Q=0,$$

然后计算：

$$K=R^{-1}B^TP.$$

环境没有 python-control，当前使用 `scipy.linalg.solve_continuous_are`。有 python-control 时走其 lqr 接口，数学目标相同。

`gain` 是得到的2×6矩阵。第一行决定左轮力矩，第二行决定右轮力矩；每个元素是对应状态的反馈系数。程序使用 u=-KX，不能忘记前面的负号。

求解后检查：P 代回 Riccati 方程的相对残差够不够小，以及 A-BK 的特征值实部是否全部为负。后者证明当前理想线性闭环渐近稳定。

### 5.4 `simulate_closed_loop()`：用反馈控制后会怎样

它先积分 `Xdot=(A-B@gain)@X`，再由各输出时刻的状态计算 `torque=-gain@X`。

这并不是“积分时忘了控制，最后才加上力矩”。控制作用已经包含在 A-BK 里；后算力矩只是把同一控制规律导出成曲线。

`X[:,-1]` 的检查只是问：“在设定的终止时刻，状态是否已经足够接近零？”默认阈值为每分量数值1e-4，位置、角度、速度的单位各不相同。它不是统一物理误差范数，也不是严格调节时间定义。改变权重或缩短仿真时长后，末值检查可能失败，即使所有闭环极点仍稳定。

### 6.1 开环六状态图

重点看**增长方向与趋势**，不要把截断后的大角度行为继续当作真实车辆预测。

### 6.2 闭环六状态图

[打开闭环图](outputs/closed_loop.png)

与开环排列相同，但时间范围到15秒。不要忽略两张图的横轴范围不同。

- theta很快从0.03 rad下降，短暂越过零后回到零：控制器允许短暂反向倾斜来同时调整位置和速度。
- x先向正方向移动，峰值约0.035 m，再回到零：轮子移动以恢复姿态，之后消除位置误差。
- 速度最终也趋近零，说明并非仅“路过参考位置”。
- psi基本为零：这次初值只激励俯仰；程序额外做了位置/偏航/俯仰混合初值检查，只打印/保存末值，没有另生成第四张图。

“Zero to numerical precision”表示结果小到浮点舍入误差量级，例如1e-16。这不是可解释的真实微小摆动。程序只调整显示尺度，没有篡改CSV数据。

要判断响应，依次看：最终偏差、峰值、是否越过零、衰减快慢、速度是否同时归零。仅看theta一张图不足以说明整车六状态都收敛。

### 6.3 左右轮力矩图

[打开力矩图](outputs/torques.png)

横轴秒，纵轴N·m。实线是左轮，虚线是右轮。当前对称俯仰实验两条线几乎重合。

负力矩只是相对于所定义正方向的反向转矩，不是错误。两条线重合也不是少画了一条。

此图回答“控制律要求多大力矩”，不回答“真实电机能否输出”。当前没有限幅；若有电机峰值/连续转矩限制，必须再加入饱和并重新仿真。

## 7. main() 把这些步骤串起来

执行顺序：

1. 创建输出目录，设置绘图字体大小。
2. `build_state_space()` 得到模型。
3. `check_system()` 检查矩阵、开环模态和可控性。
4. `simulate_open_loop()` 生成无输入响应。
5. `design_lqr()` 计算反馈增益。
6. `simulate_closed_loop()` 生成反馈响应和力矩。
7. 用混合初值额外检查偏航等状态能否收敛。
8. `plot_states()` 保存两张状态图，再保存一张力矩图。
9. 写CSV、JSON、Markdown报告，并在终端打印关键结果。

`if __name__ == '__main__'` 的作用是：直接运行这个文件时才执行 main；其他脚本只导入它的函数时，不会自动画图或开始仿真。

输出目录通过 `Path(__file__)` 定位，因此从哪个终端目录运行都能写到同一处。Matplotlib 的 Agg 后端表示“保存图片、不弹窗”；绘图缓存放在项目输出目录，不修改系统Python。

## 9. 第一次自己运行或修改，建议按这个顺序

### 第一步：不改参数，复现当前结果

```bash
/home/mechcid/lagarain/.venv/bin/python /home/mechcid/lagarain/simulation/lqr_simulation.py
```

打开 outputs 中的三张图和 REPORT.md。成功运行不会自动弹出图窗；这是当前设定。

### 第二步：只改变初始俯仰，例如0.03改为0.01 rad

其他状态仍为零，Q/R和机器人参数不动。在这个没有饱和的线性模型中，闭环状态和力矩曲线应整体缩小到约三分之一，形状和时间尺度相同。

开环由于使用固定0.20 rad停止阈值，终止时间会改变，因此不能直接拿两张不同终止时间的图按同一个横向比例比较。

### 第三步：加一个小偏航扰动

把 initial_state 改为 `(0., 0.02, 0.03, 0., 0., 0.)`。观察偏航角回零，同时左右力矩不再完全相等。

只给x或psi扰动且theta初始为零时，当前 main 中“开环俯仰必须增长”的专用检查可能不适用；先沿上面的混合初值方式操作。

### 第四步：保持初值，只改一组权重

例如把 r_weights 从 `(10,10)` 调大到 `(20,20)`，观察峰值力矩、姿态与位置响应的变化。通常更惩罚力矩会让控制更克制，但不能保证每个状态的每个峰值都单调下降。

调Q/R应观察全部状态和力矩，不要只以theta回零快为标准。若收敛变慢导致15秒末值检查失败，先看闭环极点和响应，不要直接认定控制器失稳。

### 第五步：替换真实机器人参数

将质量、惯量、尺寸换成自己的值后重跑。不要改动 K 的某几个元素“凑”结果；K应由新模型和你选择的权重重新求解。

每次运行覆盖同名输出。想保留两组实验用于比较，先把当前 outputs 中的报告、CSV和图片复制到另一个实验目录。

## 10. 当前验证已经说明什么，还没有说明什么？

已经说明：示例参数下矩阵可计算，开环具有倒立摆不稳定性，六维线性系统可控，LQR闭环极点均在左半平面，小扰动仿真收敛，积分与矩阵指数结果相符。

没有说明：真实电机力矩是否足够、采样与延迟是否可接受、大角度或大范围转向时是否稳定、噪声和摩擦下是否仍有同样表现。

你目前只需把它理解为：**把已有局部方程变成了一个可以反复改变参数和初值、观察响应的数值实验。**
